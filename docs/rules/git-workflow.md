# Git 同步、开发基线与上传规则

适用于本项目每次文件改动、源码同步、提交和上传；2026-11-02 用户明确要求。此规则是根 AGENTS.md 的组成部分。

- 唯一开发与发布基线是 `git@github.com:forfunly/seineshop.git` 的远程 `main`。以远程 package.json、锁文件、源码结构及依赖版本为准；不继续使用之前独立创建的本地 Hydrogen 2026.10.2 / React 19 版本，不擅自升级或将两代 API 混用。2026-11-02 远程为 Hydrogen 2026.4.7 / React 18；今后以每次同步后的实际版本为准。
- 每次开始新改动前先查看本地状态、执行 `git fetch origin`、检查远程新增提交及差异。工作区已跟踪 main、干净且可快进时，用 `git pull --ff-only origin main` 同步后再修改。远程无更新也要明确核对，不能沿用上轮检查结果。
- 若有未提交改动、历史分歧、冲突或工作区尚未建立远程基线，先保留工作成果并处理同步；禁止盲目 pull、覆盖远程或继续基于过期源码开发。本地独立工程与远程的首次对齐涉及较大改动，先在 Plan Mode 给出保留方案，经用户确认后实施；不能自行删除旧文件或 Git 历史。
- 每次新改动（包括代码和规则文档）的目标分支均为 `main`。适用验证通过后，按明确文件范围准备本地提交，检查差异、敏感内容和忽略规则，不把本地旧工程、无关改动、凭据、生成物或依赖整体打包提交。
- **每一次 push 之前必须停下来问用户**：说明本次提交、文件清单、验证结果及目标 `origin/main`，得到针对本次推送的明确同意后才能执行。用户未回复或只说以后要上传 main 均不是本次批准；不得用其他命令、工具或 GitHub API 绕过。2026-11-02 用户已撤销先前普通 main push 的免确认约定；该旧约定不再生效。
- 上传前再次检查远程。若 main 已前进，先获取新提交并处理并发改动、复核差异和受影响验证，不强推、不擅自 rebase。上传后读取远程 main 的提交哈希，确认本次提交已在远程；本地 commit 或 push 命令已执行不等于上传已验证。
- 用户对某次 push 的同意只覆盖已说明的提交与目标，不自动涵盖后续 push、生产部署、删除、密钥/.env、CI/CD、schema/迁移、系统设置、全局依赖或受限 Git 操作。上传前核对当前自动化配置；若本次 push 会触发尚未授权的生产部署，先准备可审查的改动，再单独确认生产发布。不擅自新增或修改自动部署。
- 首次源码对齐的实际状态和证据见项目连接记录及验收，不能仅凭本规则认定已完成。只修改规则时应提交范围明确的文档变更，保留远程前台源码、package.json 和锁文件；不得把规则提交夹带为整套旧本地前台覆盖。
- 本文件放于 `docs/rules/`，使用英文 kebab-case 命名；该目录仅保存项目规范，不放凭据、下载包或构建输入，不自动清理。按用户最新决定，首次对齐只合并既有规则，不迁入旧前台或旧管理脚本，也不建立旧工程备份；删除旧文件须另按明确路径获得授权。
