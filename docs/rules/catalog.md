# 参考网站、商品采集与数据规范

采集、选品、定价、变体、商品数据、Metafields 或 Metaobjects 任务必须读取。

## 参考网站、选品与定价

- 本文件是仓库内参考策略、来源限制和商业规则的长期记录。`../DEVELOPMENT-MEMORY.md` 若存在仅作补充；关键约束必须保存在本文件，缺失时不能推测其中内容。
- 面向消费者的页面、metadata、结构化数据、公开资源及浏览器/服务端构建资源不得出现 TVCMALL 来源品牌、采购链接、来源价或内部采购记录；公共参数仅使用明确获准展示的字段。内部管理脚本与来源映射不得导入前台。部署前执行来源暴露审计，不能把已有审计的字符串检查当作所有内部数据均未暴露的充分证明。

- 用户指定主要参考网站：TVCMALL，`https://www.tvcmall.com/`。后续选品及网站建设以该站为主要参考，涵盖商品品类、分类与导航、列表与详情页结构及选购流程；具体实施前查看相关真实页面，按 SeineShop 实际商品与业务内容适配。
- 从 TVCMALL 采集的商品，SeineShop 售价固定按对应商品及规格的来源价格的 **2 倍** 设置：`SeineShop selling price = TVCMALL source price × 2`。
- 核对并保留来源链接、对应规格、采集时价格及币种；不同规格分别计算。币种不同时须先明确汇率换算，不能把不同币种的数值直接翻倍当作本站售价。
- 这一定价规则用于后续采集商品；记录规则不等于自动批量修改店铺现有商品。实际采集上架或修改价格时按用户具体任务执行。
- 本站库存、价格展示、物流、售后及其他服务承诺使用本站真实数据与政策，参考网站的承诺不能直接当作本站已提供的服务。

## 商品 URL 与 handle

- 新商品上架时必须同步明确设置 Shopify Product 的 `handle`，与本站最终商品名称和实际品类一致，不只改标题而遗漏 URL；使用简洁、可读的小写英文单词，以连字符分隔，保留有用的品牌、品类和适配机型，避免关键词堆砌、来源站品牌或无意义编号。
- 同一 SPU 合并为一个 Product 时使用同一个商品 handle，各 SKU 通过变体区分；handle 不应写入仅适用于某个变体的颜色或尺寸。创建前检查唯一性，发生冲突时使用稳定且有意义的区分项，保留来源 SPU 与本站商品 ID/handle 映射。
- 重复采集及后续调整标题时先读取既有 handle，保持已发布 URL 稳定，不随每次标题或价格更新自动重命名。确需修改既有 handle 时，将旧 URL 到新 URL 的永久重定向、本站内链、canonical、sitemap 及适用的 hreflang/结构化数据 URL 一并处理；在实际 Headless/Oxygen 站点验证旧链接能正确跳转，不能仅凭后台已创建重定向认定前台生效。
- 上架或变更后通过 API 读回 handle，检查正式商品路径 `/products/{handle}` 与对应商品/变体匹配；仅对按任务实际发布的商品进行线上可访问性及 SEO 核验。记录规范不代表自动批量重命名现有商品。

## 商品合并与 SKU 变体

- 采集同一商品链接时，属于同一 SPU 的多个 SKU 必须归入同一个 Shopify Product，各 SKU 对应其 Product Variant，不按 SKU 拆成多个独立商品。
- 颜色、尺寸、适配机型等可售规格按来源真实结构映射为商品选项及变体；每个 SKU 分别保留来源标识、规格组合、价格、库存状态和对应图片，不因归并 SPU 而丢失差异。
- 定价按每个 SKU 独立计算：对应 SKU 的来源价格 × 2；不同 SKU 来源价格不同时，保留各自计算后的售价。
- 保留来源链接、来源 SPU/SKU 标识与 Shopify 商品/变体的映射。重复采集时先匹配既有商品与变体并更新，避免重复创建同一 SPU 或 SKU；不能仅凭标题相似、同类目或同品牌判定同款。
- 实施后读回检查同一 SPU 下的 SKU 数量、规格组合、来源映射、图片及逐 SKU 价格，确认归并完整且没有错误合并不同款。

## 采集数据与 Shopify 自定义数据

- 采集字段较多时，使用 Shopify 原生字段、元字段（Metafields）和元对象（Metaobjects）有结构地保存，避免把所有参数拼进商品描述而无法单独读取或维护。
- 商品标题、描述、售价、SKU、销售选项与变体、主图和相册优先使用对应的 Shopify 原生字段与商品媒体。
- 商品或变体的扩展参数（例如尺寸、材质、包装清单）使用合适类型的元字段；先复用适合的现有定义，确保字段归属到对应商品或变体。
- 多个商品共用或需要独立维护的结构化内容（例如适配说明、规格表、材质介绍）使用元对象，由商品元字段引用；附加说明图片或文件可通过文件引用关联 Shopify 中的文件。
- 实施顺序为：核对并建立字段/对象定义 → 写入采集值与引用 → 通过 API 读回核对。先在文档中明确字段名称、类型、归属、用途与访问范围，再实施定义或结构变更，并遵守项目授权边界。
- 来源价格、来源链接、采集时间和内部备注作为内部追溯数据保存，默认不向 Storefront 公开；前台需要展示的参数按需配置读取权限，并在 Hydrogen 页面显式查询和渲染。
