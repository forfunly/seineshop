# 工程、目录与验收详细规范

工程结构、可复用工具、框架接入、验证或交付任务必须读取；沿用根 AGENTS.md 的操作边界。

- 开始改动、同步、提交及上传前还必须读取 [Git 工作流](git-workflow.md)。远程 `origin/main` 是唯一开发基线；首次对齐只合并项目规则，不迁入旧本地独立工程的代码、工具或依赖。

## 代码留存与复用

- 项目根目录为各开发者本地克隆的仓库目录，路径相对此目录，不绑定操作系统、用户名或本机绝对路径。本项目后续编写的可复用脚本、采集处理逻辑和网页代码均保存在该目录下，按用途归档，不能只留在聊天记录、临时终端命令或项目外的临时目录中。
- 商品采集、来源数据整理、SPU/SKU 归并、价格计算及 Shopify 管理工具放在 `scripts/`；网页、组件与前台业务逻辑放在 `app/`；实施方案与验收记录分别放在 `docs/plans/`、`docs/qa/`。
- 编写新功能前先检查现有实现，优先复用或完善已有脚本与模块，避免为同一流程重复创建功能相同的脚本。临时排查形成稳定、需要重复执行的流程后，应保存为项目脚本。
- 新增或修改可复用工具时，补充 README 中的用途、运行命令、输入输出及所需配置说明，并执行适用验证。凭据仍仅使用获授权的本地 `.env`，不得硬编码进脚本或示例。

## 本地工具与交接资料

- Node 版本遵循 package.json 与 README；工具路径按开发者实际环境解析，不把某台设备的运行时绝对路径写入通用规则，不擅自修改系统配置。
- `.cache/tooling/`：项目内临时工具（npm、Shopify Toolkit 文档/技能），按工具英文名称分目录；不修改应用依赖和锁文件、不纳入提交、不自动清理。
- `.cache/handoffs/`：内部交接包原文与快照；每次独立命名目录，根 README 说明用途、命名和保留规则。不得作为消费者资源或整体覆盖源码；逐项比较后合并内部证据。

- `.react-router/`、`dist/`、`build/`、`.cache/`、`node_modules/`：工具生成文件、项目级缓存及本地依赖，不纳入源代码提交，不自动清理。npm 共享缓存被占用时可用命令级 `--cache .cache/npm`，不更改系统或全局 npm 配置。
- `.cache/` 也用于隔离浏览器验收的生成配置；与构建产物一样不参与 ESLint 源码扫描。应用、脚本与测试继续接受原有检查，不通过排除业务代码处理错误。

- `.env`：获授权的本地连接参数；必须被 Git 忽略，不输出其内容。
- 管理 App 的身份、实际权限、接入历史与已有授权见 [项目连接状态](../project-state.md)；处理连接或凭据前必须读取，不从旧安装记录推断当前已接通。
- `scripts/`：本地管理工具与验证脚本，使用英文 kebab-case 命名；只读为默认，不内嵌凭据，不导入前台构建。保留有用工具，不自动删除临时文件。

- 不自动删除文件。临时产物需要清理时先列明路径并询问用户。

## 实施规则

- 先更新规范，再调整目录或工程实践；大改动先提交方案，用户确认后实施。
- 大改动包括架构或框架迁移、跨模块公共接口/数据流重构、依赖主版本升级，以及批量商品/业务行为调整；不单以文件数或行数判断。普通局部修复和已确认范围的规则整理按既定目标实施，命中根规范红线仍须先授权。需要方案时先用 Plan Mode 进行只读调查、列明范围/风险/验收，经确认后动手；客户端无法切换模式时先提交方案等待确认，不直接实施。
- 已批准方案的后续实现、必要局部修复和验证不反复申请方案批准；常规检查及最小内部测试按根规则自主执行。发现阻碍先诊断和处理，只有需要新的受限操作、关键业务信息或超出已批准范围的重大方案变化才暂停相关步骤，并继续独立工作。不能仅因调用真实API、留下未发布测试记录、跨多个文件或存在无关未提交文件，就自行增加等待用户的门槛。
- 优先采用 Shopify 官方 Hydrogen；先确认实际版本，依照该版本文档开发，禁止混用新旧 API。
- `tests/` 当前使用 Node 内置 `node:test` 与 `node:assert/strict`，ESLint 测试配置必须匹配实际框架，不套用需要 Jest 运行时的规则；不得为修复检查配置而引入无关测试框架或跳过测试检查。
- 使用 Shopify 托管结账；只实现已经验证可用的功能。
- 不通过注释错误、忽略类型检查或加入绕过标记处理故障。
- 密钥、token、密码不得进入代码、commit 或日志；不要求用户在聊天发送验证码。

## 前台开发与 skill 复用

依据用户2026-11-17的要求，后续前台开发遵守以下约定：

- 以[商品规范](catalog.md#参考网站选品与定价)指定的核心竞品为参考，实施前查看其真实网站框架、菜单、页面结构及 UI，再按 Seine Shop 实际商品与已实现能力改造和迭代细节；保持全站导航、命名及交互一致。
- 前端采用响应式设计，覆盖桌面、平板和手机；验证菜单、图片、文本、表单及主要操作在不同视口下可用，不出现意外横向溢出。
- 搭建过程中使用现有 `npm run dev` 提供本机实时预览，将实际可访问的预览地址告知用户，便于边搭建边查看效果；监听范围沿用本项目本机限制，受阻时说明原因，不将预览称为正式上线。
- 后续逐步完善首页、商品详情页、搜索及购物车；每轮明确当前功能范围和验收要求，不把长期方向当作本轮已实现或已验收。
- 开工前检查当前可用 skill，优先复用与任务、技术栈及实际版本匹配的能力，并读取对应说明；同时复用项目已有组件、工具及流程，避免重复实现。现有 skill 不能替代项目规则、官方版本文档或实际验证；不因复用要求自行安装全局依赖。
- 全站设计、实现和验收遵循[全站 SEO 规范](seo.md#全站-seo-规范)，包含商品测评博客及其商品推荐链接。

## 客户资料、订阅与订单归属

- 客户档案、姓名、地址、邮件营销状态及订单沿用 Shopify 原生数据，不另建同步数据库。账户页读取和修改仅以 Customer Account 登录身份为准，不接受浏览器指定客户 ID、邮箱或授权令牌；所有账户响应禁止共享缓存。
- 邮件营销订阅和退订为独立、明确的用户操作，不因注册、登录或修改姓名自动订阅；读取 Shopify 实际状态，区分已订阅、待确认、未订阅及不可用。保存资料或订阅设置后读回核验，业务错误、权限不足或结果不确定时不显示成功、不自动重复提交。
- 本轮资料与订阅逻辑归属现有 `app/routes/account.profile.jsx`、`app/graphql/customer-account/`、`app/lib/`，回归检查放 `tests/`；页面延续现有账户样式和英/日/德语言。订单继续通过托管结账创建并由 Customer Account API 读取，购物车身份来自服务端登录会话。普通购买、询价草稿及未完成结账分别验收，不造正式交易补证据。

## 验证与交付

### GA4 电商事件归属（2026-11-17）

- 服务端扩展方案已在当前会话确认，实施归属沿用 `app/lib/`、`app/routes/`、`tests/` 及原分析方案/QA。服务端模式下加购与购买必须指定唯一发送方；不以任意 event_id 宣称 GA4 自动去重。购买按已付款通知，并要求结账完成时的允许分析回执，使用订单 transaction_id 与订单私有 JSON 元字段 `seine_analytics.ga4_purchase` 的 CAS 状态；定义、权限及密钥必须另行授权后才创建。网络不确定保留人工核对，不盲目重发；2xx 不等于入库。该扩展在实际配置与验证之前不改变生产事件归属。
- 用户询问用途后已明确继续 Clarity 与 GA4 两项。Clarity 沿用现有组件/模块目录；只在分析允许且非账户/购物车/私有工作台时加载，拒绝不加载，撤回执行 consentv2 拒绝并停止采集；表单及私有内容显式遮罩。项目编号为公开安装标识，不是后台 API token；不将后台认证会话或密钥带入前台。

- 沿用本店现有 GA4 测量 ID，不新增广告平台、凭据或依赖。`session_start` 由 GA4 自动生成；商品页负责 `view_item`，购物车成功响应负责 `add_to_cart`，Shopify 托管结账像素独占 `begin_checkout`、`add_payment_info`、`purchase`，避免前台按钮与结账回调双报。
- 公共事件映射与发送逻辑放在 `app/lib/`，React 接入放在 `app/components/`；结账自定义像素原文放在 `scripts/ga4-checkout-pixel.js`，仅用于后台配置，不导入前台、不自动执行或连接生产。测试放在 `tests/`；沿用现有分析方案与 QA 文档记录，不另建同用途资料。
- 新增电商事件遵循 Shopify 分析许可，失败操作不报成功；金额、币种与实际商品数据一致，GA4 商品数组超过 200 项时拆分加购事件。结账只携带经校验的匿名 GA client/session 标识，使用购物车属性传递，不放入 URL，不发送邮箱、电话、地址、结账 token 或支付信息。像素按订单号去重购买事件，发送到 GA 队列不等于后台已入库。
- 当前任务的方案确认只授权代码、配置准备及内部验证；不自动启用生产像素，不扩大历史同意门控的发布范围。生产像素连接、Git push 和部署分别确认；测试事件使用隔离的本地接收器，避免伪造生产购买收入。真实测试店支付验收与正式 GA4 入库证据单独记录。

### 通用验收

- 执行前核对 package.json、锁文件和测试配置。当前命令入口为 `npm run lint`、`npm run codegen`、`npm run build`，测试使用 `node --test tests/*.test.mjs`。`codegen` 只生成 GraphQL/路由类型，不是全项目类型检查；未提供 `typecheck`、`test:admin` 或 `admin:check` 时不得假设存在。历史检查结果保存在 QA 记录，不作为本次通过依据。
- `npm ci` 用于首次准备或锁文件变化后的依赖安装，不是每次编辑必跑的检查；已安装且适用的依赖可复用。新增全局依赖及系统配置仍遵守授权红线。
- 本地启动使用远程工程 `npm run dev`，核对该版本 CLI 的监听选项并仅监听本机；旧本地 Vite 的 `--host 127.0.0.1` 不能直接照搬到 Hydrogen CLI。不主动建立公开隧道。
