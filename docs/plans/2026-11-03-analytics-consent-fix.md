# 全站分析与同意状态修复方案

日期：2026-11-03（Asia/Shanghai）。状态：待用户确认；尚未修改前台。问题证据见 [失败验收](../qa/2026-11-03-analytics-consent.md)。本方案为 T10 失败后的修复节点，不能把排查完成当作验收通过。

## 目标行为

访客在 Cookie 设置中拒绝分析后，GA4 不再继续发送分析事件；刷新仍尊重已保存的选择。允许时正常初始化，后续撤回时停止追踪。Privacy API 尚未准备好时默认不开始追踪。

## 建议实施范围

1. 沿用 Hydrogen 2026.4.7 的 `Analytics.Provider`、`useAnalytics` / `useCustomerPrivacy`，不升级 SDK、不新增营销平台或依赖。将 root 中无条件执行的 GA4 初始化收敛为与 Customer Privacy 状态同步的模块；初始化幂等，避免路由切换或 StrictMode 重复发送。
2. 采用基本同意模式：未获允许时不加载/发送 GA4 分析；拒绝或撤回时停发并同步 Google 同意状态，不以“无 Cookie 请求”绕过拒绝。无广告业务授权时不额外启用广告用途。现有统计 ID 保持不变，不申请新凭据。
3. 启用 Shopify 官方隐私横幅，展示遵循店铺实际地区配置；页脚补充可重新打开 Cookie 偏好的入口及英语/日语/德语文案。使用已有样式、路由、CSP nonce 和语言体系；不新建一套自定义同意数据库。
4. 变更前读取现有本地化、Footer 和 CSP 实现。可复用的同意同步逻辑保存于 `app/lib/`，组件放 `app/components/`，行为测试沿用 Node 测试规范。仅按实际需要触及 root、Footer、语言字典与对应样式，不顺带处理其他旧提示。

## 验收

- 先用可控测试覆盖 API 未就绪、允许、拒绝、撤回、重复初始化及路由切换；检查 `npm run lint`、测试、构建、来源暴露审计及 Shopify Toolkit 的版本匹配校验，明确其限制。
- 独立浏览器上下文检查首次访问、拒绝、允许、撤回与刷新保留；网络层核对 GA4 是否按同意状态发送，而不仅看脚本标签或 Cookie。记录 SDK 的异步就绪时序。
- 桌面/手机检查横幅与重新设置入口，验证键盘及 EN/JA/DE 文案。地区适用性依据真实配置与可验证的结果，不伪造地域或生产结果。
- 保留结账密码，不下单；不将 GA4 后台归因、购买转化或所有地区合规性宣称为已完成。修复完成即更新 HTML 与 Markdown 流程图、任务状态和验收依据；失败继续留在修复节点。
