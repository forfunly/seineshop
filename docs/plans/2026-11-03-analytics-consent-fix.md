## GA4 服务端回传与 Clarity（2026-11-17，方案已确认）

- 当前会话用户确认服务端回传方案。随后询问 Clarity 的用途与必要性，并明确选择“两项都继续接入”。沿用现有目录和测量 ID，保留此前六事件成果。
- 成功加购在服务端按 Shopify 前后快照生成金额与商品；配置服务端发送且取得匿名 client/session 标识时，浏览器不再重复发送同一事件。未配置时保留原浏览器行为。分析传输不阻塞购物车或重试加购。
- 购买只接受配置店铺的 `orders/paid` 签名通知，校验原始请求 HMAC、金额、币种、测试标记及结账时的分析同意。订单按 Shopify presentment 金额映射，禁止发送客户身份、联系方式、地址及支付资料。
- 为避免结账中途撤回同意后仍按旧属性回传，额外要求结账像素在完成时提交允许分析回执。回执携带服务端签名匿名上下文，与 Admin 读取的订单属性相同才受理；未付款先保存回执，付款通知与回执无论谁先到均可完成。没有最终回执则不回传，可能少计但不绕过同意。
- Clarity 使用官方浏览器安装脚本，项目编号由商家项目读回；只在允许分析的公开页面加载，账户/购物车/搜索/私有页面不采集，表单显式遮罩，撤回后 stop。遵循官方 consentv2；不依赖其拒绝后的无 Cookie 采集模式。
- 服务端代码沿用 `app/lib/*-server`（实际文件以 `.server.js` 命名）和 `app/routes/`；回归放 `tests/`。使用订单私有 JSON 元字段 `seine_analytics.ga4_purchase` 保存领取/已接受/不确定状态，CAS 避免并发发送。配置、定义和权限仅准备代码，未获单独批准不在后台创建。
- GA4 不承诺任意事件 event_id 的跨端去重；购买使用稳定 transaction_id，并由服务端单独负责。网络结果不确定时保留待核对状态，不自动双发。HTTP 2xx 只表示请求接受，不声称 GA4 已入库。
- 实施前先完成规则、官方文档核对及代码；所需 GA4 API secret、Shopify 通知签名密钥、订单读写权限和本地配置另行列明申请。生产启用、推送和部署分别确认。真实 GA4 入库、生产通知与结账撤回同意的闭环未验证前不得称全部接通。
- URL 不变，新增通知入口 private/no-store/noindex，不加入 sitemap，运行既有 sitemap 回归。验证涵盖 HMAC、错误店铺/主题、未付款、拒绝分析、金额、并发与重试、凭据不外泄，以及 lint/codegen/build 和来源审计。

## 目标行为

访客在 Cookie 设置中拒绝分析后，GA4 不再继续发送分析事件；刷新仍尊重已保存的选择。允许时正常初始化，后续撤回时停止追踪。Privacy API 尚未准备好时默认不开始追踪。

## 建议实施范围

1. 沿用 Hydrogen 2026.4.7 的 `Analytics.Provider`、`useAnalytics` / `useCustomerPrivacy`，不升级 SDK、不新增营销平台或依赖。将 root 中无条件执行的 GA4 初始化收敛为与 Customer Privacy 状态同步的模块；初始化幂等，避免路由切换或 StrictMode 重复发送。
2. 采用基本同意模式：未获允许时不加载/发送 GA4 分析；拒绝或撤回时停发并同步 Google 同意状态，不以“无 Cookie 请求”绕过拒绝。无广告业务授权时不额外启用广告用途。现有统计 ID 保持不变，不申请新凭据。
3. 启用 Shopify 官方隐私横幅，展示遵循店铺实际地区配置；页脚补充可重新打开 Cookie 偏好的入口及英语/日语/德语文案。使用已有样式、路由、CSP nonce 和语言体系；不新建一套自定义同意数据库。
4. 变更前读取现有本地化、Footer 和 CSP 实现。可复用的同意同步逻辑保存于 `app/lib/`，组件放 `app/components/`，行为测试沿用 Node 测试规范。仅按实际需要触及 root、Footer、语言字典与对应样式，不顺带处理其他旧提示。
